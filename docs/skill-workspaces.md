# Inspect and fork a skill

Select a skill name in Global, a Deck, Drafts, or an external source to open its files. The version selector distinguishes the Catalog source, installed copy, working copy, upstream snapshot, and baseline when available. Markdown is sanitized; binary files show metadata and large text is truncated. Invalid YAML can still be inspected.

For an External or Vendor skill, **Fork** creates one persistent working copy of the entire skill directory. Saving changes only that copy. Review its diff, validate it, then choose **Apply** to register a Vendor with the same name. Existing Active / Off / Archive state and Deck membership are preserved; an unmanaged candidate is installed when applied. Authored and Draft skills are viewable here without converting them into external forks.

**Check upstream** is explicit. Commit counts include only changes in the skill directory. Unknown baselines, missing paths, unavailable repositories, and discontinuous history are distinct states. Fetching never advances the baseline. Merge the latest version into the working copy, resolve conflicts, and apply successfully to advance it. Conflicting files can retain the working version or take the upstream version, including additions, deletions, and binaries. The original upstream copy lives in `upstream/<name>`; customizations live in `vendor/<name>`.

**Codex** starts a locally installed `codex app-server` only when sending a prompt. The adapter accepts CLI 0.164.x and uses the existing ChatGPT login; run `codex login` separately if needed. Other CLI versions fail closed until their protocol and isolation are verified. Manual editing does not require Codex. The UI shows conversation history, approval requests, and a stop action. Skill Loom never applies changes merely because a turn completed.

Native shell tools are disabled. Codex requests commands through `skill_exec`; each invocation requires explicit UI approval, including read commands and attached scripts. Approved commands run with an explicit sandbox that limits writes to the working copy and enables network access only when the approved request asks for it. Commands have a 10-second limit and each output stream is capped at 64 KiB. Stop terminates the owned command before interrupting the turn. This is a write boundary, not a guarantee that all host files are unreadable; inspect commands and access requests before approving them.

Workspace files, conversation metadata, immutable Git snapshots, tracking information, and apply journals live under the selected Catalog's ignored `.skill-loom/` directory. They remain local and are not synchronized by Git. Discard moves the working copy and its conversation to Trash without changing the installed skill. Apply failures restore the prior Inventory and installed content while preserving work; interrupted applies are recovered at startup. A remaining journal is reported as requiring recovery and blocks another apply or discard.

The local API accepts same-host JSON requests on loopback / `.localhost` hosts. Skill paths cannot traverse directories or follow nested symlinks. Source hooks, submodules, and downloaded skill scripts are not run during snapshot fetching or validation. Dependencies outside the skill directory, binary preview, selected-commit merging, and scheduled refreshes are outside this workflow.

Tests use temporary Catalogs, local Git repositories, and a fake JSON-lines App Server. They verify protocol and UI behavior without live model inference or personal credentials; model response quality is not a validation guarantee.
